# 06. Триггеринг (гл. 20)

Пользователь **триггерится** в анализ, если для него есть (потенциальная) разница между его вариантом и контрфактическим. У нетронутых эффект = 0, они только добавляют шум. Триггерные события логировать в рантайме.

## Типы
1. **Намеренное частичное покрытие** (только США, только Edge). «Смешанных» пользователей и все их действия после контакта включать.
2. **Условный контакт:** дошёл до checkout, использовал фичу, увидел страницу отписки или погодный ответ.
3. **Расширение покрытия:** бесплатная доставка от $35 → от $25. Триггерятся только те, у кого корзина **$25–35** в момент checkout.
4. **Изменение покрытия:** условия пересекаются. Оба варианта вычисляют контрфактическое условие, триггер — только при различии.
5. **ML-модели:** в обоих вариантах запускать обе модели, логировать фактический и контрфактический выход, триггер — если выходы различаются. Цена: удвоенный inference и скрытая разница в латентности.

## Численный пример
- Конверсия 5%, MDE 5% относительных: 16·0.0475/(0.0025)² = **121,600** пользователей.
- Триггер на checkout: 10% начинают, половина покупает (p=0.5): 16·0.25/(0.025)² = **6,400** триггерных → ~64,000 всего. **Примерно вдвое быстрее.**

## Оптимальный и консервативный триггер
Оптимальный — только с реальной разницей. Консервативный (шире) не ломает анализ, только теряет мощность. Примеры:
- при нескольких Treatment хранить флаг «отличались»;
- если контрфактический лог сломан — post-hoc условие «начал checkout».

## Разбавление на всю аудиторию (diluted / site-wide impact)
**Ловушка:** «+3% выручки у 10% пользователей = +0.3% в целом» — НЕВЕРНО, реально от 0% до 3%:
- изменение в checkout, а вся выручка идёт через checkout → **+3% в целом**;
- пользователи, тратящие 10% от среднего → 3% × 10% × 10% = **0.03%**.

Обозначения: ω — все, θ — триггерные; Δθ = M_θT − M_θC; τ = N_θC/N_ωC.
- **Разбавленный эффект = Δθ · N_θ / (M_ωC · N_ω)** (абсолютный эффект на триггерных, отнесённый к общему итогу контроля).
- Эквивалентно: (Δθ / M_ωC) · τ.
- Наивное δθ·τ = (Δθ/M_θC)·τ верно, **только если триггерные — случайная выборка**. Иначе ошибка в M_ωC/M_θC раз.
- Ratio-метрики разбавлять по специальным формулам (Deng & Hu 2015). Парадокс Симпсона возможен: ratio у триггерных растёт, а глобально падает.

## Проверки доверия к триггеру
1. **SRM на триггерной популяции.** Если в целом SRM нет, а в триггерной есть — контрфактический триггер сделан неверно.
2. **Анализ дополнения:** scorecard по **никогда не триггерившимся** должен выглядеть как A/A. Больше значимых метрик, чем ожидается, значит условие триггера неверно.

## Ловушки
1. **Крошечные сегменты:** +5% на 0.1% пользователей дают τ=0.001 (закон Амдала). Исключение — обобщение маленькой идеи. Пример MSN: Hotmail в новой вкладке (+8.9% у триггерных) обобщили до выдачи в новой вкладке (+5% clicks/user на 12M).
2. **Триггерный пользователь остаётся в анализе до конца эксперимента.** Анализ по дням или сессиям недооценит эффект, если Treatment снижает возвраты.
3. **Производительность контрфактического логирования** скрыта. Помогают: логировать время каждой модели и **A/A′/B** (A′ = контроль + контрфактический лог; A против A′ показывает цену логирования). Shared control с контрфактическим логом почти невозможен.

## Открытые вопросы
- Единица триггера: только данные после триггера, вся сессия, день или с начала эксперимента (проще, мощность чуть ниже).
- Графики по времени с накоплением пользователей дают ложные тренды, обычно «убывающий эффект». Лучше по дням с пользователями, пришедшими и триггернувшимися в этот день.
