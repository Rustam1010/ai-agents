name: ramp-plan
description: Составить план раскатки по фреймворку SQR (гл. 15) — кольца, MPR неделю, post-MPR, holdout или реплика, алерты и автоматическое выключение.
---

1. Выясни: риск изменения (UI, backend, инфраструктура, платёжный поток), нагрузка, есть ли кольца (команда, сотрудники, beta, дата-центр), число вариантов, нужен ли долгосрочный замер.
2. План по фазам (`knowledge/book/02-design-decisions-ramp.md`):
   - **Pre-MPR:** кольца с длительностью и критериями перехода; автоматическое наращивание трафика; NRT-guardrails (ошибки, краши, латентность, выручка) с порогами автоматического выключения;
   - **MPR:** доля (50/50, или 1/k при k вариантах), **≥ 1 неделя** (`abstat.py duration`), дольше при novelty/primacy; без peeking;
   - **Post-MPR:** ступени под нагрузку (например, 75%) ≤ дня с пиком трафика;
   - **Holdout или реплика** — только если нужно (критерии из гл. 15). Если нужен holdout для малого эффекта — на MPR, не 90/10.
3. Учти: смена долей во время анализа → не объединять периоды наивно (Симпсон); SRM проверять на каждой ступени.
4. После 100%: удалить мёртвый код или сделать параметр значением по умолчанию.
5. Итог — таблица: фаза · доля · длительность · критерии перехода · алерты.
